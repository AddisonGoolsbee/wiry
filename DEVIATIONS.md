# Deviations, cut corners, and known gaps

Running log of every simplification made against full Scapy parity. Nothing here is
hidden from users: the README links this file, and the launch benchmark will state
the supported surface explicitly.

Status key: **OPEN** = still a gap · **CLOSED** = resolved, kept for history.

---

## Scope decisions (deliberate, made 2026-09-15)

| # | Decision | Rationale | Status |
|---|---|---|---|
| S1 | Protocol scope limited to Ether, ARP, IPv4, IPv6, TCP, UDP, ICMP, ICMPv6, DNS, DHCP/BOOTP, VLAN(802.1Q), Raw, Padding | Scapy registers 1,746 layers on import and 4,160 `Packet` subclasses with contrib. Full parity is multi-person-year. This set covers the overwhelming majority of real scripts. | OPEN |
| S2 | No live capture or injection in v1 (`sniff`, `send`, `sendp`, `sr`, `sr1`, `srp`) | Requires raw sockets, root, and per-OS backends; untestable in CI. Parse/build is where the measured 1000x lives. API shape is reserved so capture is additive, not breaking. | OPEN |
| S3 | Standalone, clean-room, no Scapy import at runtime | Scapy is GPL-2.0-only. Importing it would relicense this project and forfeit both commercial adopters and the Rust crates.io audience. | CLOSED |
| S4 | Unimplemented protocols dissect to `Raw`, exactly as Scapy does for layers it lacks | Preserves correct round-trip bytes for everything, at any depth. | CLOSED |
| S5 | Name `packetry` is provisional and not yet registered on PyPI/crates.io/GitHub | Deliberately not squatting until the project is real. | OPEN |

## Provenance policy (licensing-critical)

See `CONTRIBUTING.md`. Summary: protocol field layouts are written from RFCs and IANA
registries, never transcribed from `scapy/layers/*.py`. Reimplementing an API is
settled fair use (*Google v. Oracle*, 2021); copying field-table source is not.
Golden test vectors come from Wireshark/tshark and hand-built RFC vectors, not from
running Scapy, because a machine-generated corpus derived from GPL code is a grey area.

## Engineering shortcuts

| # | Shortcut | Consequence | Status |
|---|---|---|---|
| E1 | Field model is a static table per protocol, but a field may now carry a condition over its own layer's header bytes (`FieldDesc::cond`). ICMP uses it for the whole RFC 792/950/1191/4884 type-dependent layout: `id`/`seq`, `gw`, `ptr`, `reserved`/`length`/`nexthopmtu`, the three timestamps and `addr_mask` are each present only for the types that define them, the header grows to 12 or 20 octets where the type requires it, and a read, write or construction of a field the message does not carry is refused rather than aliasing another field's octets. Two fields may share a name when their conditions are disjoint, which covers `MultipleTypeField` | Remaining: a condition sees only its own layer's header, so a field whose presence depends on the enclosing layer cannot be expressed — DNS's TCP length prefix (RFC 1035 §4.2.2) is declared with a condition that is always false, and `ICMP.ext`/`extpad` (RFC 4884 §7) live past the quoted datagram, in what this model calls the payload, so they exist as names only. No arbitrary computed fields, and no conditions definable from Python (see E3) | PARTIAL |
| E2 | IPv4/TCP/DHCP options are read and written: `pkt[TCP].options` returns a named list, and `TCP(options=[('MSS', 1460)])` encodes one. Raw bytes accepted too, and `raw_options()` returns them. A parsed list feeds straight back to the constructor: an option the parser has no name for is labelled with its code in decimal, and that label encodes as that code again, so parse-then-rebuild is byte-exact for DHCP option 60 and every other unnamed code | Remaining: SACK blocks are not split into edge pairs | PARTIAL |
| E3 | Layers are definable from Python. Subclassing `Packet` with a `fields_desc` registers the layer in Rust at class-definition time; `packetry.fields` supplies `ByteField`, `XByteField`, `ShortField`, `XShortField`, `LEShortField`, `IntField`, `XIntField`, `LEIntField`, `LongField`, `XLongField`, `LELongField`, `BitField`, `IPField`, `IP6Field`, `MACField`, `StrFixedLenField`, `StrField` and `FlagsField`. `bind_layers(UDP, MyProto, dport=9999)` makes dissection reach it and makes stacking write the parent's field back. From then on it behaves as a generated built-in: `/` stacking, `pkt[MyProto]`, `in`, field get/set, `show()`, `summary()`, `bytes()`, dissection from a capture, and `columns()`/`filter()`. The declaration is data, never a callback: no Python runs during dissection | Remaining: a declared layer is a flat fixed-width table plus at most one trailing variable-length `StrField`, refused at class-definition time where the `StrField` is not last, so it has no conditional fields (E1), no computed lengths or checksums, and no option region (E2); `X*` fields are plain integers rather than hex-rendered; a binding tests equality on integer fields only, and it outranks the parent's own built-in guess where both match; layer names are global to the process and a built-in name cannot be taken over; registration is append-only and leaks, capped at 1,024 layers and 1,024 bindings | PARTIAL |
| E4 | `show()` output formatting matched by eye, not byte-for-byte against Scapy | Cosmetic divergence possible in edge cases | OPEN |
| E5 | pcapng **reading** implemented (`pcapng.rs`: SHB, IDB with `if_tsresol`, EPB, SPB, both endiannesses, unknown blocks skipped, trailing-length validated); **writing** not implemented | Modern captures read fine and yield the same `pcap::Record` as classic pcap, so callers need not care which format they got. Still missing: writing pcapng; per-interface link types when one file mixes them (`FileHeader.linktype` reports the first IDB's, though each interface's own `if_tsresol` is honoured per packet); multi-section files with differing link types (endianness and the interface table do reset at a new SHB, the reported link type does not); Name Resolution Blocks; Decryption Secrets Blocks; per-packet options. Resolutions other than 10^-6 and 10^-9 truncate to microseconds, since `Record.ts_frac` has no finer unit | OPEN |
| E6 | No IPv6 extension-header chain walking beyond the common set | Exotic chains fall back to `Raw` | OPEN |
| E7 | DHCP options (RFC 2132) are parsed into a named item list via `Packet::options`; the raw `options` field still exposes the untouched bytes. The magic cookie belongs to BOOTP's trailing `options` field, where RFC 2131 §3 puts it, so the DHCP layer starts at the first option and has `options` as its only field | Per-option lookup works for the common codes (message type, lease time, requested address, masks, routers, name servers, client id, parameter request list). Still missing: option 82 sub-options stay opaque bytes, long-option concatenation across repeated codes (RFC 3396) is not implemented, and options past the first End are discarded rather than read from `sname`/`file` overload (RFC 2131 §4.1, option 52) | OPEN |
| E8 | DNS record sections are now parsed: `dns::parse_records` returns `qd`/`an`/`ns`/`ar` over the whole message, including name compression (RFC 1035 §4.1.4) with bounded pointer following, and decodes RDATA for A, NS, CNAME, SOA, PTR, MX, TXT and AAAA | Remaining: the DNS-over-TCP two-octet length prefix is not stripped, so TCP-carried messages must be de-framed by the caller; EDNS0/OPT pseudo-records (RFC 6891) get no special treatment (no extended rcode, UDP payload size, or option list) and DNSSEC types (DS/RRSIG/NSEC/DNSKEY) fall back to raw RDATA bytes, as does every other unlisted type; names render without a trailing dot and without escaping dots inside a label; the layer's payload still dissects as `Raw`, so bytes round-trip unchanged. `pkt[DNS].qd`/`an`/`ns`/`ar` are exposed from Python and listed by `fields()`, but they are parser-backed accessors (`proto::accessor_names`), not flat fields: they have no fixed offset or width and cannot be assigned. One message decodes at most 256 KB of names in total (`dns::MAX_DECODED_NAME_BYTES`) and returns what it read when that runs out, because a two-octet compression pointer yields up to 255 octets and a message claiming 65,535 records in every section otherwise amplified 2.75 MB of input into 568 MB of output; no real message comes within a thousandth of the budget | OPEN |
| E9 | Source MAC defaults (`Ether.src`, `ARP.hwsrc`) stay zero instead of being filled from the host interface | Scapy queries the live interface; this build is offline-only (see S2), so constructed frames are deterministic rather than host-dependent. Byte output differs from Scapy for these two fields unless set explicitly | OPEN |
| E10 | Two more default-construction differences, both deliberate. A bare `DNS()` is the 12-byte header alone, where Scapy's ships a sample question record for `www.example.com`; writing a question needs the record encoder that E8 does not have, and inventing a hostname in a default is worse than an empty section. A bare `ICMP(type=13)` leaves the three timestamps zero, where Scapy fills them from the host clock, which is the E9 problem in another form: a default that changes between two runs of the same script | Every other layer is byte-identical to Scapy on default construction. `dev/api_audit.py` reports these two and ARP's interface MAC as the only remaining mismatches | OPEN |
| E11 | `flags` is a rich value, not a string. `pkt.flags` returns a `FlagValue` that compares equal to its integer and to its letter string, converts with `int()`/`str()`/`bool()`, hashes as its integer, exposes every bit as a boolean attribute where a concatenation of names is the AND of those bits (`.SA`), writes through to the packet when a bit is assigned, supports `&`, `|`, `^` and their in-place forms against an int, a string or another `FlagValue`, iterates its set names, and reprs as `<Flag 18 (SA)>`. Every `FieldKind::Flags` field has it, IPv4's and BOOTP's included. Names longer than a letter are joined with `+` (`MF+DF`), in the engine's renderer as well, so bulk columns and per-packet reads keep agreeing | Two bugs fell out of the work: an unassigned bit carries an empty name, which every string contains, so `BOOTP(flags="B")` used to set all sixteen; and TCP's control bits are nine wide, not eight, since NS (RFC 3540) takes the low bit of the reserved field. Bulk paths (`field_column`, `columns`) still return the plain string, which costs one set lookup on the per-packet read path and no allocation | CLOSED |
| E12 | `Padding` is excluded from every enclosing length and checksum, and floats to the end during assembly: `IP()/Padding("abc")` has `len == 20` in a 23-byte frame, and `Raw/Padding/Raw/Padding` emits both `Raw` parts first. Dissection produces `Padding` too — IPv4, IPv6 and UDP declare the extent their length field claims, the walk stops there, and the trailer on a frame padded to Ethernet's 60-octet minimum becomes a `Padding` layer instead of transport data | Remaining: stacking `Padding` onto an already-dissected packet appends its bytes as payload rather than as a layer, because a materialised packet cannot be turned back into a field spec (same cause as the note in `__truediv__`). A capture clipped by the snaplen keeps the lengths the wire gave, since they describe bytes that were never captured; only the IPv4 header checksum, which covers present bytes, is still recomputed | PARTIAL |
| E13 | The conveniences scapy's suite leans on are implemented: `str` payloads (`Raw("abc")`, `pkt / "abc"`, `"abc" / pkt`, `add_payload`) encoded as latin-1, integer layer indexing (`pkt[0]`, `pkt[-1]`), `getlayer(IP, ttl=3)` with field filters and an occurrence count, the `pkt[IP::{"ttl": 3}]` slice form, `ls(pkt, verbose=True)`, iteration yielding one independent copy, and `copy()`. `wrpcap()` already accepted a mix of packet types | Address generators (`IP(dst=["a","b"])`, `IP(ttl=(5,10))`, `Net`) and hostname resolution in address fields are **out of scope and not planned**: a generator is a distinct feature that multiplies one declaration into many packets, and resolving a name at build time would put DNS in the build path. They are the 6 remaining failures in `dev/scapy_suite.py` along with file-like and gzip capture input | PARTIAL |
