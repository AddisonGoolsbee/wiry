# Deviations, cut corners, and known gaps

Running log of every simplification made against full Scapy parity. Nothing here is
hidden from users: the README links this file, and the launch benchmark will state
the supported surface explicitly.

Status key: **OPEN** = still a gap · **CLOSED** = resolved, kept for history.

---

## Scope decisions (deliberate, made 2026-09-15)

| # | Decision | Rationale | Status |
|---|---|---|---|
| S1 | Protocol scope was Ether, Loopback (DLT_NULL/DLT_LOOP), CookedLinux (LINUX_SLL, LINUX_SLL2), ARP, IPv4, IPv6, TCP, UDP, ICMP, ICMPv6, DNS, DHCP/BOOTP, VLAN(802.1Q), Raw, Padding; sixty more layers were added from `dev/protogen/specs/`, at the depth the **Protocol coverage** table below states one row at a time | Scapy registers 1,746 layers on import and 4,160 `Packet` subclasses with contrib. Full parity is multi-person-year. This set covers the overwhelming majority of real scripts. | OPEN |
| S2 | Live capture and injection are being added behind the `live` feature, off by default. `sniff(offline=...)` is complete and needs no feature, no privileges and no network; `sniff(iface=...)`, `AsyncSniffer`, `send`, `sendp`, `sr`, `sr1`, `srp` and `srp1` are implemented against the same state machine and need the feature; without it every one raises `CaptureUnavailable` (a subclass of `OSError`) naming the rebuild command | The capture backend needs raw sockets, root, and per-OS libraries, so it stays untestable in ordinary CI and out of the default build. Driving the whole state machine from `offline=` is what makes it testable at all: counters, deadline, the three filter stages and the callback contract are proved with zero privileges, and the live backend becomes an I/O shim over proven logic. Privileged round-trip checks live in `dev/live/`: `netns_check.py` over a veth pair on Linux, and `loopback_check.py` on macOS, where `lo0` is DLT_NULL rather than Ethernet. | PARTIAL |
| S3 | Standalone, clean-room, no Scapy import at runtime | Scapy is GPL-2.0-only. Importing it would relicense this project and forfeit both commercial adopters and the Rust crates.io audience. | CLOSED |
| S4 | Unimplemented protocols dissect to `Raw`, exactly as Scapy does for layers it lacks | Preserves correct round-trip bytes for everything, at any depth. | CLOSED |
| S5 | Name `wiry` is provisional and not yet registered on PyPI/crates.io/GitHub | Deliberately not squatting until the project is real. | OPEN |

## Provenance policy (licensing-critical)

See `CONTRIBUTING.md`. Summary: protocol field layouts are written from RFCs and IANA
registries, never transcribed from `scapy/layers/*.py`. Reimplementing an API is
settled fair use (*Google v. Oracle*, 2021); copying field-table source is not.
Golden test vectors come from Wireshark/tshark and hand-built RFC vectors, not from
running Scapy, because a machine-generated corpus derived from GPL code is a grey area.

## Engineering shortcuts

| # | Shortcut | Consequence | Status |
|---|---|---|---|
| E1 | Field model is a static table per protocol, but a field may now carry a condition over its own layer's header bytes (`FieldDesc::cond`). ICMP uses it for the whole RFC 792/950/1191/4884 type-dependent layout: `id`/`seq`, `gw`, `ptr`, `reserved`/`length`/`nexthopmtu`, the three timestamps and `addr_mask` are each present only for the types that define them, the header grows to 12 or 20 octets where the type requires it, and a read, write or construction of a field the message does not carry is refused rather than aliasing another field's octets. Two fields may share a name when their conditions are disjoint, which covers `MultipleTypeField` | Remaining: a condition sees only its own layer's header, so a field whose presence depends on the enclosing layer cannot be expressed — DNS's TCP length prefix (RFC 1035 §4.2.2) is declared with a condition that is always false, and `ICMP.ext`/`extpad` (RFC 4884 §7) live past the quoted datagram, in what this model calls the payload, so they exist as names only. No arbitrary computed fields, and no conditions definable from Python (see E3) | PARTIAL |
| E2 | IPv4/TCP/DHCP options are read and written: `pkt[TCP].options` returns a named list, and `TCP(options=[('MSS', 1460)])` encodes one. Raw bytes accepted too, and `raw_options()` returns them. A parsed list feeds straight back to the constructor: an option the parser has no name for is labelled with its code in decimal, and that label encodes as that code again, so parse-then-rebuild is byte-exact for DHCP option 60 and every other unnamed code. Writing the field on an *already dissected* packet resizes the option region and moves `ihl`/`dataofs` with it, rather than writing over whatever followed; a region wider than those four-bit fields can describe (40 octets for both IPv4 and TCP) is refused instead of wrapping. Bulk (`field_column`, `columns`) and per-packet reads return the same parsed list | Remaining: SACK blocks are not split into edge pairs. A derived field the caller pinned stays pinned, so scapy's habit of keeping a wire-read `dataofs` while adding options is not reproduced: wiry recomputes unless you set it, and scapy's own output matches wiry's once its derived fields are cleared | PARTIAL |
| E3 | Layers are definable from Python. Subclassing `Packet` with a `fields_desc` registers the layer in Rust at class-definition time; `wiry.fields` supplies `ByteField`, `XByteField`, `ShortField`, `XShortField`, `LEShortField`, `IntField`, `XIntField`, `LEIntField`, `LongField`, `XLongField`, `LELongField`, `BitField`, `IPField`, `IP6Field`, `MACField`, `StrFixedLenField`, `StrField` and `FlagsField`. `bind_layers(UDP, MyProto, dport=9999)` makes dissection reach it and makes stacking write the parent's field back. From then on it behaves as a generated built-in: `/` stacking, `pkt[MyProto]`, `in`, field get/set, `show()`, `summary()`, `bytes()`, dissection from a capture, and `columns()`/`filter()`. The declaration is data, never a callback: no Python runs during dissection | Remaining: a declared layer is a flat fixed-width table plus at most one trailing variable-length `StrField`, refused at class-definition time where the `StrField` is not last, so it has no conditional fields (E1), no computed lengths or checksums, and no option region (E2); `X*` fields are plain integers rather than hex-rendered; a binding tests equality on integer fields only, and it outranks the parent's own built-in guess where both match; layer names are global to the process and a built-in name cannot be taken over; registration is append-only and leaks, capped at 1,024 layers and 1,024 bindings; a layer's bit offsets are sixteen bits, so a `StrFixedLenField` is at most 8,191 octets wide, refused at declaration rather than after padding a default out to the width asked for; a `FlagsField` naming more flags than its width has bits is refused too, since those bits exist nowhere | PARTIAL |
| E4 | `show()` output formatting matched by eye, not byte-for-byte against Scapy | Cosmetic divergence possible in edge cases | OPEN |
| E5 | pcapng **reading** implemented (`pcapng.rs`: SHB, IDB with `if_tsresol`, EPB, SPB, both endiannesses, unknown blocks skipped, trailing-length validated); **writing** not implemented | Modern captures read fine and yield the same `pcap::Record` as classic pcap, so callers need not care which format they got. A packet block naming an interface no IDB described is skipped, since nothing fixes its link type. Still missing: writing pcapng; per-interface link types when one file mixes them (`FileHeader.linktype` reports the first IDB's, though each interface's own `if_tsresol` is honoured per packet); multi-section files with differing link types (endianness and the interface table do reset at a new SHB, the reported link type does not); Name Resolution Blocks; Decryption Secrets Blocks; per-packet options. Resolutions other than 10^-6 and 10^-9 truncate to microseconds, since `Record.ts_frac` has no finer unit | OPEN |
| E6 | No IPv6 extension-header chain walking beyond the common set | Exotic chains fall back to `Raw` | OPEN |
| E7 | DHCP options (RFC 2132) are parsed into a named item list via `Packet::options`; the raw `options` field still exposes the untouched bytes. The magic cookie belongs to BOOTP's trailing `options` field, where RFC 2131 §3 puts it, so the DHCP layer starts at the first option and has `options` as its only field | Per-option lookup works for the common codes (message type, lease time, requested address, masks, routers, name servers, client id, parameter request list). Still missing: option 82 sub-options stay opaque bytes, long-option concatenation across repeated codes (RFC 3396) is not implemented, and options past the first End are discarded rather than read from `sname`/`file` overload (RFC 2131 §4.1, option 52) | OPEN |
| E8 | DNS record sections are now parsed: `dns::parse_records` returns `qd`/`an`/`ns`/`ar` over the whole message, including name compression (RFC 1035 §4.1.4) with bounded pointer following, and decodes RDATA for A, NS, CNAME, SOA, PTR, MX, TXT and AAAA | Remaining: the DNS-over-TCP two-octet length prefix is not stripped, so TCP-carried messages must be de-framed by the caller; EDNS0/OPT pseudo-records (RFC 6891) get no special treatment (no extended rcode, UDP payload size, or option list) and DNSSEC types (DS/RRSIG/NSEC/DNSKEY) fall back to raw RDATA bytes, as does every other unlisted type; names render without a trailing dot and without escaping dots inside a label; the layer's payload still dissects as `Raw`, so bytes round-trip unchanged. `pkt[DNS].qd`/`an`/`ns`/`ar` are exposed from Python and listed by `fields()`, but they are parser-backed accessors (`proto::accessor_names`), not flat fields: they have no fixed offset or width and cannot be assigned. One message decodes at most 256 KB in total (`dns::MAX_DECODED_NAME_BYTES`) and returns what it read when that runs out, because a two-octet compression pointer yields up to 255 octets and a message claiming 65,535 records in every section otherwise amplified 2.75 MB of input into 568 MB of output. The budget charges TXT as well as names: each character-string becomes an owned string, so RDATA of N zero octets yields N empty strings, and uncharged that turned 17 MB of input into 656 MB. No real message comes within a thousandth of the budget | OPEN |
| E9 | Source MAC defaults (`Ether.src`, `ARP.hwsrc`) stay zero at build time. `sendp` and `srp` fill an unset `Ether.src` from the outgoing interface at *send* time, on a copy | Scapy queries the live interface while building, which makes `bytes(Ether())` depend on the host. Keeping the fill in the send path is what leaves construction reproducible and `dev/build_matrix.py` at 38/38 without becoming environment-dependent. Remaining: `pcap::Device` carries no hardware address, so the address is read from `/sys/class/net/<if>/address` and is `None` on every other platform, which every caller treats as an ordinary outcome; `ARP.hwsrc` and `ARP.psrc` are not filled at all, so an ARP request built without them asks on behalf of 0.0.0.0. Byte output still differs from Scapy for these fields when built rather than sent | PARTIAL |
| E10 | Two more default-construction differences, both deliberate. A bare `DNS()` is the 12-byte header alone, where Scapy's ships a sample question record for `www.example.com`; writing a question needs the record encoder that E8 does not have, and inventing a hostname in a default is worse than an empty section. A bare `ICMP(type=13)` leaves the three timestamps zero, where Scapy fills them from the host clock, which is the E9 problem in another form: a default that changes between two runs of the same script | Every other layer is byte-identical to Scapy on default construction. `dev/api_audit.py` reports these two and ARP's interface MAC as the only remaining mismatches | OPEN |
| E11 | `flags` is a rich value, not a string. `pkt.flags` returns a `FlagValue` that compares equal to its integer and to its letter string, converts with `int()`/`str()`/`bool()`, hashes as its integer, exposes every bit as a boolean attribute where a concatenation of names is the AND of those bits (`.SA`), writes through to the packet when a bit is assigned, supports `&`, `|`, `^` and their in-place forms against an int, a string or another `FlagValue`, iterates its set names, and reprs as `<Flag 18 (SA)>`. Every `FieldKind::Flags` field has it, IPv4's and BOOTP's included. Names longer than a letter are joined with `+` (`MF+DF`), in the engine's renderer as well, so bulk columns and per-packet reads keep agreeing | Two bugs fell out of the work: an unassigned bit carries an empty name, which every string contains, so `BOOTP(flags="B")` used to set all sixteen; and TCP's control bits are nine wide, not eight, since NS (RFC 3540) takes the low bit of the reserved field. Bulk paths (`field_column`, `columns`) still return the plain string for a *flags* field, which costs one set lookup on the per-packet read path and no allocation; *option* fields now return the same parsed list from both. A name matching no flag raises rather than reading as zero, as scapy does, and matching is whole-token: substring matching meant that with names `a`, `ab` and `b` the wire value 2 read back as 7 | CLOSED |
| E12 | `Padding` is excluded from every enclosing length and checksum, and floats to the end during assembly: `IP()/Padding("abc")` has `len == 20` in a 23-byte frame, and `Raw/Padding/Raw/Padding` emits both `Raw` parts first. Dissection produces `Padding` too — IPv4, IPv6 and UDP declare the extent their length field claims, the walk stops there, and the trailer on a frame padded to Ethernet's 60-octet minimum becomes a `Padding` layer instead of transport data | Remaining: stacking `Padding` onto an already-dissected packet appends its bytes as payload rather than as a layer, because a materialised packet cannot be turned back into a field spec (same cause as the note in `__truediv__`). A capture clipped by the snaplen keeps the lengths the wire gave, since they describe bytes that were never captured; only the IPv4 header checksum, which covers present bytes, is still recomputed | PARTIAL |
| E13 | The conveniences scapy's suite leans on are implemented: `str` payloads (`Raw("abc")`, `pkt / "abc"`, `"abc" / pkt`, `add_payload`) encoded as latin-1, integer layer indexing (`pkt[0]`, `pkt[-1]`), `getlayer(IP, ttl=3)` with field filters and an occurrence count, the `pkt[IP::{"ttl": 3}]` slice form, `ls(pkt, verbose=True)`, iteration yielding one independent copy, and `copy()`. `wrpcap()` already accepted a mix of packet types | Address generators (`IP(dst=["a","b"])`, `IP(ttl=(5,10))`, `Net`) and hostname resolution in address fields are **out of scope and not planned**: a generator is a distinct feature that multiplies one declaration into many packets, and resolving a name at build time would put DNS in the build path. `rdpcap` and `PcapReader` now accept a binary stream as well as a path, which is what lets scapy's OSS-Fuzz regression inputs run against us; the stream is written to a temporary file first, because the reader indexes records by offset into one mapped buffer. gzip input is still not accepted. They are the remaining failures in `dev/scapy_suite.py` | PARTIAL |

| E15 | `sniff` is keyword-only and takes `iface`, `count`, `store`, `prn`, `filter`, `lfilter`, `timeout`, `stop_filter`, `offline`, `quiet`, `promisc`, `snaplen`, plus the wiry extension `where=`. `count=0` is unbounded, `store=0` returns an empty `PacketList`, and `timeout` is scapy's wall-clock deadline for the whole call, not libpcap's read timeout. Filters AND together cheapest first: `filter=` BPF, then `where=`, then `lfilter=`. `AsyncSniffer` has `start`, `stop`, `join`, `.results` and `.running`, and `stop()` is honoured between packets on the offline driver too | Remaining, all deliberate: scapy is positional-tolerant where this is keyword-only; `session=`, `opened_socket=`, `started_callback=`, `L2socket=` and `monitor=` are not accepted and raise `TypeError` rather than being silently ignored; `offline=` takes a path or a `PacketList`, and a plain list of packets raises `NotImplementedError` naming `wrpcap` rather than growing a second state machine that never touches a capture buffer; `quiet=True` suppresses the printing of `prn`'s return value, which is the only output `sniff` produces here; `count` counts packets that survived every filter, as scapy's does; a `timeout` no `Duration` can hold (infinity, `1e300`) is no deadline at all, i.e. exactly `timeout=None`, where it used to panic the Rust side, and a negative one still expires at once; a BPF `filter=` needs the `live` feature even offline, because compiling one is libpcap's job, and without it raises `CaptureUnavailable` saying so. `AsyncSniffer` always installs a stop check on the offline driver, so that one takes the per-packet slow path even with no user callback. Live, `sniff(iface=...)` installs `filter=` on the handle so BPF runs in the kernel, releases the GIL across every read and polls `count`, `timeout` and the stop flag between reads rather than per matched packet; a callback-free live sniff runs the loop in 250 ms slices with the GIL released, reacquiring only to check for a signal so that an unbounded `sniff` still answers Ctrl-C. A live `AsyncSniffer` is a Rust thread owning the handle: `stop()` sets a flag the loop polls between reads, `join()` waits with the GIL released, and dropping one stops and joins it, with an `atexit` hook over a `WeakSet` of live sniffers as a second line. Those waits run in the same 250 ms slices the capture loop does, with a signal check between them, so Ctrl-C interrupts a shutdown as well as a capture; a `Drop` cannot raise, so an interrupt that lands during one is handed back to whatever runs next. A `prn` given to a live `AsyncSniffer` therefore runs on a non-Python thread and reacquires the GIL per packet, which is scapy's contract for async callbacks — and a `prn` calling `stop()` or `join()` on its own sniffer gets `RuntimeError: cannot join current thread`, which is what `threading.Thread.join()` says and what the offline driver in the same class already raised; the capture is still stopped, only the wait is refused. `start`, `stop` and `join` are serialised by a lock the sniffer holds only across the state change and never across a wait, so two threads cannot both start one sniffer, and one run is all a sniffer gets: starting a finished one raises rather than silently discarding its `.results` | PARTIAL |
| E16 | `conf` is a two-attribute stand-in for scapy's: `conf.iface`, resolved from libpcap on first read and settable, and `conf.verb`. `get_if_list`, `get_if_addr`, `get_working_if` and the wiry-only `interfaces()` are real where the `live` feature is on | Remaining: scapy's `conf` carries dozens of knobs (`conf.L3socket`, `conf.route`, `conf.checkIPaddr`, `conf.promisc`, …) and none of them exist. `conf.verb` is read by `send`, `sendp` and the `sr` family to decide whether to print a summary line, and by nothing else. `get_if_addr` returns the first IPv4 address or `0.0.0.0`, with no notion of scapy's routing table | OPEN |
| E17 | `send` and `sendp` take `x`, `inter`, `loop`, `count`, `verbose`, `return_packets` and `iface`. The whole list is serialised in the facade and crosses into Rust once; the repeat and the `inter` pacing happen there, so a `sendp` of a thousand frames is one crossing. `loop` repeats until interrupted, with a signal check between passes. `send` writes IPv4 datagrams to a raw socket with the header included, letting the kernel route and resolve | Remaining, all deliberate: `send` is IPv4-only and an IPv6 packet raises `NotImplementedError` naming `sendp` — raw bytes as well as a built packet, since past the facade the only thing between them and the `AF_INET` socket is a version nibble — because the raw socket is `AF_INET` and a second address family is a second backend; anything `send` is handed that is not an IPv4 datagram (an `Ether()`-wrapped one meant for `sendp`, a line of text) raises `ValueError` rather than being written to the wire with a destination read out of octets 16..20, and the check reads RFC 791's version, IHL and total length directly, because the dissector is *told* the link type rather than asked to detect it and so reports IPv4 for any buffer long enough; anything that is not a packet, bytes or a `str` raises `TypeError`, since `bytes(3)` is three zero octets and `sendp([1, 2, 3])` would otherwise put three all-zero frames on the wire; `inter=` must be finite and raises `ValueError` otherwise, because a pause of `Duration::MAX` is a hang; raw IPv4 sending is refused outright on Windows, where it is restricted by the OS; `socket=` and `realtime=` raise `NotImplementedError` rather than being ignored, and `iface_hint=` is accepted and unused; `return_packets=True` returns a plain list of what was handed in, not a `PacketList`, since the sent frames are never indexed into a capture buffer; `verbose` prints one summary line rather than scapy's dot per packet | PARTIAL |
| E14 | Reply matching for `sr`/`sr1` (`answers.rs`) is a closed table: ICMP and ICMPv6 echo, an ICMPv4 error (types 3, 4, 5, 11, 12) quoting the datagram that provoked it, a swapped TCP or UDP address and port pair, that plus a DNS **response** (QR set) carrying the id a DNS **query** asked with, and an ARP reply for the address asked about. Anything else is not an answer — there is deliberately no fallback on the address pair alone, since a wrong match silently corrupts a user's results where a missed one is visible in `unanswered`. Every rule pins the addresses down in both directions, the two echo rules and the quoted header included, because `sr` opens the handle promiscuously and an error or a reply meant for a third party is on the wire to be mismatched. An ICMP error is matched on the quoted header's source and destination, protocol and IP id, then the first 8 transport octets: the addresses come first because wiry builds every datagram with `id = 1` and a default `ICMP()` payload is the same eight octets every time, so a multi-target `sr()` would otherwise pair every reply with whichever probe came first. The TCP ack relation is computed by `ack_consistent` but never gates a match, so a RST answering a SYN still counts | Remaining: ICMPv6 errors (RFC 4443 types 1-4) quote an IPv6 datagram and are not matched, so an IPv6 traceroute has no reply rule; a reply is matched against one sent packet at a time, with no notion of a best match when two sent packets would both accept it; the quote is read only as far as RFC 792 guarantees it (the internet header plus 64 bits), so two probes differing only past that first payload octet are still indistinguishable. `sr`, `sr1`, `srp` and `srp1` are built on it: the receive capture opens before anything is sent, `retry=N` resends the unanswered set N more times, `multi=True` collects several answers per probe, and anything `answers()` does not match is dropped rather than guessed at, so it shows up in `unanswered`. `retry=` and `multi=` both need a `timeout=` and raise `ValueError` without one, since the first round otherwise waits until every probe is answered and neither a retry round nor a `multi` collection can ever end. Scapy's *negative* `retry` (resend only while nothing at all has answered) raises `NotImplementedError`; `answered` is a plain list of `(sent, received)` pairs and `unanswered` a plain list, not scapy's `SndRcvList`/`PacketList`, since the sent packets are never indexed into a capture buffer | PARTIAL |

## Protocol coverage (the sixty layers generated from `dev/protogen/specs/`)

Sixty new `ProtoId`s were added, covering every protocol on the parity list.
`dev/protogen/README.md` explains the tool; this table is what the layers do and
do not do. **A layer that dissects its header and leaves its body as `Raw` is
listed here as exactly that.**

| # | Item | Remaining | Status |
|---|---|---|---|
| P1 | Sixty layers, all from their RFC or registry, all cited in the module and in the spec: LLC, SNAP, STP, LLDPDU, CDP, RadioTap, Dot11 with its six management bodies, SCTP, IGMP, the five RFC 4861 Neighbor Discovery messages, the four MLD messages, ESP, AH, OSPF_Hdr, RIP, BGPHeader, VRRP, HSRP, BFD, NTP, DHCP6, SNMP, TFTP, Syslog, NBNS, NBTSession, Radius, RTP, RTCP, NetflowHeaderV5, NetflowHeaderV9, IPFIX, SFlow, QUIC, WireGuard, TLS, HTTP, SSH, MQTT, ModbusADU, SMB2_Header, LDAP, SIP, FTP, SMTP, IMAP, Telnet. Dispatch reaches them from EtherType, the 802.3 length framing, the LLC SAP, the SNAP protocol id, the IP protocol number, the ICMPv6 message type, and UDP and TCP ports | Depth varies and is stated per row below. Nothing here recomputes a checksum or a length (P8) | PARTIAL |
| P2 | Deliberately out of scope on this branch, because `feat/encap` owns them: IPv6 extension headers, GRE, VXLAN, GENEVE, IP-in-IP, 6in4, 4in6, MPLS, PPPoE/PPP, GTP-U, ERSPAN | Not implemented here at all | OPEN |
| P3 | **Fixed-size record arrays stay in the payload.** A protocol whose body is `n` copies of a fixed record is dissected as far as the count, and the records themselves are `Raw`: RIP route entries (RFC 2453 §3.6), NetFlow v5 flow records, sFlow v5 samples, IGMPv3 group records (RFC 3376 §4.2.1), MLDv2 multicast address records (RFC 3810 §5.2.4), OSPF bodies (RFC 2328 §A.3.2 onwards), BGP message bodies (RFC 4271 §4.2 onwards), SCTP chunk *parameters* (the chunks themselves are parsed) | The flat model has no repeating-group construct (E1), and `options.rs`'s named-item shape is a poor fit for a homogeneous array. Reaching these needs a third value shape, which is a larger decision than this branch should take alone | OPEN |
| P4 | **Signed fields are read unsigned.** `FieldKind` has no signed integer, so NTP's `poll` and `precision` (RFC 5905 §7.3, both signed exponents) read as 0..255 | A scripting user comparing `pkt[NTP].precision` to a negative number gets the wrong answer. Adding `FieldKind::Int` is a small change but touches `field.rs`, `show.rs` and `parse.rs`, which are shared files this branch was told not to churn | OPEN |
| P5 | **RTP and RTCP are bound to no port.** Both are negotiated out of band (SDP), and every heuristic for finding them on an arbitrary even UDP port has a false-positive rate this dissector will not accept | They are reachable by `bind_layers(UDP, RTP, dport=...)` and by direct construction, and not otherwise. Dissecting a capture of RTP therefore takes one line of setup | OPEN |
| P6 | **NetFlow v9 and IPFIX data records need the template the exporter sent earlier.** That is per-session state across datagrams, which this dissector does not keep and which the FFI boundary rule makes expensive to keep in Python | Only the export header is dissected; the FlowSets and Sets are `Raw`. This is a real limitation, not a shortcut: template-based decoding is a stateful feature, not a layout | OPEN |
| P7 | **Encrypted payloads stay `Raw`, by construction.** ESP (RFC 4303 §2) past the sequence number, QUIC (RFC 9000 §12.1) past the header, WireGuard (§5.4.6) past the counter, and every TLS record body that is not a ClientHello or ServerHello | Not a gap that can be closed without keys | CLOSED |
| P8 | **No new layer recomputes a length or a checksum.** `compute.rs` handles IPv4, IPv6, TCP, UDP, ICMP and ICMPv6, and was deliberately not extended: a checksum written by a layer whose pseudo-header rules were not tested is worse than one left as it arrived | Construction emits the bytes you set and nothing else, so `bytes(IP()/SCTP())` carries `chksum == 0`. Dissection and round-trip are unaffected — this is exactly why every new layer round-trips byte-identically | OPEN |
| P9 | **Port dispatch is a heuristic, and every application layer that could be confused with a mid-stream segment carries a guard over the payload.** HTTP needs a method token or a status line, TLS a content type of 20..=24 with a 0x03xx version, BGP an all-ones marker, SMB2 its `\xfeSMB`, Modbus a zero protocol id, LDAP a BER SEQUENCE whose length fits, QUIC its fixed bit, SSH a banner or a plausible packet length, MQTT a valid type and remaining length, FTP/SMTP a reply code or an alphabetic verb, IMAP a tag or `*`/`+`. NetFlow v5, v9 and IPFIX share UDP 2055 and are told apart by their version word | Telnet on port 23 has no guard, because its stream has no start-of-message marker to test. A continuation segment on any guarded port falls back to `Raw`, which is the safe direction; a message that starts mid-capture is missed rather than mis-dissected. Dissection is still per packet: nothing here reassembles a TCP stream, so a message split across segments is only seen if its first segment carries the start | PARTIAL |
| P10 | **802.11 is the MAC header and the six management bodies, nothing more.** Control frames (RFC-equivalent IEEE 802.11-2020 §9.3.1) dissect to `Raw` past the MAC header; the FCS trailer is not stripped, so on a capture that includes it the last four octets land in the payload; QoS Control is counted in the header length but not exposed as a field; WEP/CCMP-protected bodies stay `Raw` | The information elements of the six management bodies *are* parsed, as a named item list rather than as scapy's repeating `Dot11Elt` layers | PARTIAL |
| P11 | `DHCP6`'s raw `options` field is declared at octet 4, which is right for a client/server message and wrong for a Relay-forward or Relay-reply, whose fixed part is 34 octets | The *parsed* list (`pkt[DHCP6].options`) is correct for both, because `parse_options` computes the offset from the message type; only `raw_options()` is wrong for a relay message. A conditional variable-length field would fix it and the model has no such thing (E1) | OPEN |
| P12 | **Some layer names and groupings differ from scapy's, deliberately.** mDNS and LLMNR dissect as `DNS` on ports 5353 and 5355, because RFC 6762 §18 and RFC 4795 §2 *are* the RFC 1035 message format and a second copy of the DNS record parser would be a second thing to get wrong. | T1 | **Text-line protocols do not get a third shape in the engine.** HTTP, SIP, FTP, SMTP, IMAP, Telnet and syslog are CRLF-delimited text with no fixed offsets, so a `FieldDesc` table cannot describe them. They are served instead as the **named item list `options.rs` already produces for a TLV region** — the same `Vec<Item>` through the same `ProtoDesc::parse_options` hook, the same `Cell::Opts` bulk path, the same Python value. `layers/text.rs` is the producer: line splitting, header-block end detection, RFC 9112 §5.2 obs-fold joining, RFC 9110 §5.1 name canonicalisation, start lines and reply codes. | T2 | **BER/ASN.1 gets a reader, not a compiler.** SNMP (RFC 1157 §4.1, RFC 3416 §3) and LDAP (RFC 4511 §4.1.1) have no fixed offsets *at all* — every field's position depends on the length of the one before it — so they, too, are a named item list rather than a field table. `layers/ber.rs` is 120 lines of X.690 §8: identifier and length octets, INTEGER, OBJECT IDENTIFIER, and a bounded walk over a constructed value. SNMP decodes version, community, PDU type, request id, error status and index, and every varbind as `oid -> value`; LDAP decodes messageID, the protocolOp name and its first arguments | Remaining: this is one level of structure at a time, not a schema. No BER *encoder*: these two layers dissect and round-trip, and cannot be constructed field by field | PARTIAL |
| T3 | **A malformed BER message raises nothing; scapy raises `BER_Exception`.** This is a behavioural divergence, not a missing name. CLAUDE.md §5 makes robustness the rule, so an indefinite length, a high-tag-number identifier, a length octet count above four or a length running past the buffer all end the walk and yield whatever was already decoded — an empty item list for a message that is bad from its first octet. Code that relies on catching `BER_Exception` to tell a bad message from a good one has no equivalent here and must test the decoded result instead. `dev/scapy_suite.py` lists `BER_Exception` in `OUT_OF_SCOPE` for that reason, and this row is the honest statement of what that entry hides | Remaining: there is no "was this well-formed?" signal of any kind. | T4 | **The parsed item lists are capped, and a message past the cap is silently truncated.** `text::lines` stops at 256 lines and `ber::children` at 256 elements per constructed value, which is what keeps a crafted message bounded. Measured: 709 KB of input carrying 65,536 distinct headers yields 259 items, in 0.46 ms | Remaining: the cap is a constant, not a budget, so it bounds *count* and not bytes. Neither needs DNS's owned-byte budget, and neither reports what it dropped | PARTIAL |
| G1 | `dev/protogen/` generates the layer files and the registration edits from one TOML spec per protocol, and refuses rather than guessing: a missing citation, a duplicate id or name, a field past a fixed header, two fields sharing octets with no condition, a variable-length field that is not last.
