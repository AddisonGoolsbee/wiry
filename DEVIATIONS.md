# Deviations, cut corners, and known gaps

Running log of every simplification made against full Scapy parity. Nothing here is
hidden from users: the README links this file, and the launch benchmark will state
the supported surface explicitly.

Status key: **OPEN** = still a gap · **CLOSED** = resolved, kept for history.

---

## Scope decisions (deliberate, made 2026-09-15)

| # | Decision | Rationale | Status |
|---|---|---|---|
| S1 | Protocol scope limited to Ether, Loopback (DLT_NULL/DLT_LOOP), CookedLinux (LINUX_SLL, LINUX_SLL2), ARP, IPv4, IPv6, TCP, UDP, ICMP, ICMPv6, DNS, DHCP/BOOTP, VLAN(802.1Q), Raw, Padding, plus the encapsulations of E6 (the four IPv6 extension headers, GRE, VXLAN, Geneve, MPLS, PPPoE/PPP, GTP-U, ERSPAN) | Scapy registers 1,746 layers on import and 4,160 `Packet` subclasses with contrib. Full parity is multi-person-year. This set covers the overwhelming majority of real scripts. | OPEN |
| S2 | Live capture and injection are being added behind the `live` feature, off by default. `sniff(offline=...)` is complete and needs no feature, no privileges and no network; `sniff(iface=...)`, `AsyncSniffer`, `send`, `sendp`, `sr`, `sr1`, `srp` and `srp1` are implemented against the same state machine and need the feature; without it every one raises `CaptureUnavailable` (a subclass of `OSError`) naming the rebuild command | The capture backend needs raw sockets, root, and per-OS libraries, so it stays untestable in ordinary CI and out of the default build. Driving the whole state machine from `offline=` is what makes it testable at all: counters, deadline, the three filter stages and the callback contract are proved with zero privileges, and the live backend becomes an I/O shim over proven logic. Privileged round-trip checks live in `dev/live/`: `netns_check.py` over a veth pair on Linux, and `loopback_check.py` on macOS, where `lo0` is DLT_NULL rather than Ethernet. | PARTIAL |
| S3 | Standalone, clean-room, no Scapy import at runtime | Scapy is GPL-2.0-only. Importing it would relicense this project and forfeit both commercial adopters and the Rust crates.io audience. | CLOSED |
| S4 | Unimplemented protocols dissect to `Raw`, exactly as Scapy does for layers it lacks | Preserves correct round-trip bytes for everything, at any depth. | CLOSED |
| S5 | Name `wiry` is provisional and not yet registered on PyPI/crates.io/GitHub | Deliberately not squatting until the project is real. | OPEN |

## Provenance policy (licensing-critical)

See `CONTRIBUTING.md`. Summary: protocol field layouts are written from RFCs and IANA
registries, never transcribed from `scapy/layers/*.py`. Reimplementing an API is
settled fair use (*Google v. Oracle*, 2021); copying field-table source is not.
Golden test vectors come from Wireshark/tshark and hand-built RFC vectors, not from
running Scapy, because a machine-generated corpus derived from GPL code is a grey area.

## Engineering shortcuts

| # | Shortcut | Consequence | Status |
|---|---|---|---|
| E1 | Field model is a static table per protocol, but a field may now carry a condition over its own layer's header bytes (`FieldDesc::cond`). ICMP uses it for the whole RFC 792/950/1191/4884 type-dependent layout: `id`/`seq`, `gw`, `ptr`, `reserved`/`length`/`nexthopmtu`, the three timestamps and `addr_mask` are each present only for the types that define them, the header grows to 12 or 20 octets where the type requires it, and a read, write or construction of a field the message does not carry is refused rather than aliasing another field's octets. Two fields may share a name when their conditions are disjoint, which covers `MultipleTypeField` | A layer may also carry *framing* contributed by the pair it sits in rather than by either header alone: `proto::framing_octets(parent, child)` gives DNS its RFC 1035 §4.2.2 stream length prefix, and the dissector counts those octets into the header ahead of every field. Since that moves every field, the framed layout is a second static table (`proto::fields_of(id, framed)`), not a second condition | Remaining: a *condition* still sees only its own layer's header, so a field whose presence depends on the enclosing layer is expressible only where that layer also changes the offsets, as framing does. `ICMP.ext`/`extpad` (RFC 4884 §7) live past the quoted datagram, in what this model calls the payload, so they exist as names only. No arbitrary computed fields, and no conditions definable from Python (see E3) | PARTIAL |
| E2 | IPv4/TCP/DHCP options are read and written: `pkt[TCP].options` returns a named list, and `TCP(options=[('MSS', 1460)])` encodes one. Raw bytes accepted too, and `raw_options()` returns them. A parsed list feeds straight back to the constructor: an option the parser has no name for is labelled with its code in decimal, and that label encodes as that code again, so parse-then-rebuild is byte-exact for DHCP option 60 and every other unnamed code. Writing the field on an *already dissected* packet resizes the option region and moves `ihl`/`dataofs` with it, rather than writing over whatever followed; a region wider than those four-bit fields can describe (40 octets for both IPv4 and TCP) is refused instead of wrapping. TCP SACK blocks (RFC 2018 §3) are split into a list of `(left, right)` edge pairs, and a list of pairs — or a flat list of edges — encodes back to the same octets; a SACK payload that is not a whole number of blocks keeps its raw octets rather than being silently re-cut. Bulk (`field_column`, `columns`) and per-packet reads return the same parsed list, and both now go through one `packet::options_at`, so the DHCP overload and joining of E7 cannot reach only one of them. A bulk column or filter condition resolves its field against *both* layouts a layer can take (E1 framing) before the loop starts, so a framed layer is never read through the unframed table's offsets and an unframed one never answers to a name only the framed table declares | Remaining: a derived field the caller pinned stays pinned, so scapy's habit of keeping a wire-read `dataofs` while adding options is not reproduced: wiry recomputes unless you set it, and scapy's own output matches wiry's once its derived fields are cleared | PARTIAL |
| E3 | Layers are definable from Python. Subclassing `Packet` with a `fields_desc` registers the layer in Rust at class-definition time; `wiry.fields` supplies `ByteField`, `XByteField`, `ShortField`, `XShortField`, `LEShortField`, `IntField`, `XIntField`, `LEIntField`, `LongField`, `XLongField`, `LELongField`, `BitField`, `IPField`, `IP6Field`, `MACField`, `StrFixedLenField`, `StrField` and `FlagsField`. `bind_layers(UDP, MyProto, dport=9999)` makes dissection reach it and makes stacking write the parent's field back. From then on it behaves as a generated built-in: `/` stacking, `pkt[MyProto]`, `in`, field get/set, `show()`, `summary()`, `bytes()`, dissection from a capture, and `columns()`/`filter()`. The declaration is data, never a callback: no Python runs during dissection | Remaining: a declared layer is a flat fixed-width table plus at most one trailing variable-length `StrField`, refused at class-definition time where the `StrField` is not last, so it has no conditional fields (E1), no computed lengths or checksums, and no option region (E2); `X*` fields are plain integers rather than hex-rendered; a binding tests equality on integer fields only, and it outranks the parent's own built-in guess where both match; layer names are global to the process and a built-in name cannot be taken over; registration is append-only and leaks, capped at 1,024 layers and 1,024 bindings; a layer's bit offsets are sixteen bits, so a `StrFixedLenField` is at most 8,191 octets wide, refused at declaration rather than after padding a default out to the width asked for; a `FlagsField` naming more flags than its width has bits is refused too, since those bits exist nowhere | PARTIAL |
| E4 | `show()` output formatting matched by eye, not byte-for-byte against Scapy | Cosmetic divergence possible in edge cases | OPEN |
| E5 | pcapng **reading and writing** implemented (`pcapng.rs`). Reading: SHB, IDB with `if_tsresol`, EPB, SPB, both endiannesses, unknown blocks skipped, trailing-length validated. Writing: SHB, IDB and EPB, each padded to a 4-byte boundary and closed with the trailing total length the reader validates, with `if_tsresol` declared when `nano=True`. `wrpcapng()`, `PcapNgWriter`, and any writer whose file is named `.pcapng` or `.ntar`, produce it | Modern captures read fine and yield the same `pcap::Record` as classic pcap, so callers need not care which format they got. A packet block naming an interface no IDB described is skipped, since nothing fixes its link type. What we write reads back identically through wiry's own reader, scapy 2.7.0 and dpkt, over every combination of format, resolution and compression (`dev/write_check.py`); tshark was not on the PATH when that was last run, so its half of the check has never been exercised. Still missing on the **write** side: every block but SHB, IDB and EPB — no Simple Packet Blocks, no Name Resolution Blocks, no Decryption Secrets Blocks, no per-packet options (so scapy's `pkt.comment` is dropped rather than written), one interface per section, and little-endian output only. Appending opens a *new* section rather than reusing an earlier IDB, since a packet block may only name an interface described in its own section. Still missing on the **read** side: per-interface link types when one file mixes them (`FileHeader.linktype` reports the first IDB's, though each interface's own `if_tsresol` is honoured per packet); multi-section files with differing link types (endianness and the interface table do reset at a new SHB, the reported link type does not); Name Resolution Blocks; Decryption Secrets Blocks; per-packet options. Resolutions other than 10^-6 and 10^-9 truncate to microseconds, since `Record.ts_frac` has no finer unit | PARTIAL |
| E6 | Encapsulation is walked rather than stopped at. The previous wording here — "no IPv6 extension-header chain walking beyond the common set", "exotic chains fall back to `Raw`" — understated the gap twice over: **no** extension header was walked, so hop-by-hop options and destination options (both ordinary), Router Alert, MLD and every fragmented IPv6 flow were invisible, and losing a tunnel loses everything under it, not one leaf protocol. Now: the four RFC 8200 §4 extension headers (Hop-by-Hop 0, Routing 43, Fragment 44, Destination Options 60) are layers of their own that chain into each other and out to the real transport; GRE (RFC 2784 with RFC 2890 key and sequence); VXLAN (RFC 7348); Geneve (RFC 8926); IP-in-IP and 6in4/4in6 (RFC 2003, RFC 4213, protocols 4 and 41 over both versions); MPLS (RFC 3032) with the label stack walked to its bottom; PPPoE Discovery and Session with PPP (RFC 2516, RFC 1661); GTP-U (3GPP TS 29.281) including its extension-header chain; ERSPAN Type I, II and III (draft-foschiano-erspan-03). They nest: the total depth is bounded at 32 layers by `packet.rs`, each header advances the offset so no chain can be self-referential, and a Fragment header past offset 0 carries no transport header, as IPv4 already did. `columns()` and `filter()` see inner layers, and the bulk path is asserted to agree with the per-packet one | Remaining: **MPLS and GTP-U have no protocol field**, so what follows is read from the payload's first nibble — 4 or 6 for an IP version (RFC 4385 §3 is what makes that a signal rather than a guess), and for MPLS anything else as an Ethernet pseudowire (RFC 4448 §4.6). That last arm is a guess and can be wrong the other way too: an Ethernet pseudowire with no control word whose destination MAC begins `4x` or `6x` reads as an IP datagram. Nothing in the packet can tell the two apart, so the ambiguity is the protocol's, not this implementation's, and it is why a control word (nibble 0) stays `Raw`. A leading zero nibble is a pseudowire control word, which has no layer here, so that payload stays `Raw` rather than being read as a frame shifted by four octets; scapy has an `EoMCW` layer and reads it, which is why one scapy regression test skips here instead of passing. GRE version 1 (PPTP, RFC 2637) is read with the version-0 layout, so its payload length and call id appear as `key` and its acknowledgement number is unread; the RFC 1701 source-route list is not walked, only its two-octet checksum/offset pair accounted for. `IPv6ExtHdrRouting` names its fields after Type 0, the only layout RFC 8200 §4.4 gives, so for a Type 4 (segment routing) header everything past `segleft` is `reserved`+`addresses` by name only. The option regions of Hop-by-Hop and Destination Options parse and encode (Pad1, PadN, RouterAlert, JumboPayload, HAO, PDM) but there is no automatic PadN insertion, so a block written by hand must land the header on an 8-octet boundary — scapy's `autopad` pseudo-field has no equivalent and `len` is recomputed from the span, skipped rather than rounded when it does not fill whole units; Geneve's `optionlen` works the same way over 4-octet units, and its option TLVs are opaque bytes. A region *wider* than the count can name is refused rather than skipped, since 256 octets of Geneve options would otherwise write 64 into six bits as 0 and swallow the block, and 2,054 octets of IPv6 options would clamp `len` to 255 and read the eight octets past the claim as the transport header; `PPPoE.len` and `GTP_U_Header.length` are refused past 65,535 for the same reason, where nothing encloses them that would catch the overflow first. A clipped capture keeps every one of these as the wire gave it. ERSPAN Type I has no layer object, because it has no header: GRE 0x88BE with the sequence bit clear stacks `Ether` directly. Stacking `ERSPAN_II` sets GRE's sequence bit and the word that comes with it, since without them the frame it built dissected back as a Type I with the mirrored frame eight octets out of place. ERSPAN Type III's platform-specific subheader is one opaque `platform` field rather than scapy's separate `ERSPAN_PlatformSpecific` layer. VXLAN-GPE, L2TP, Teredo, IPsec (ESP/AH), SRv6 and NSH are not implemented at all | PARTIAL |
| E7 | DHCP options (RFC 2132) are parsed into a named item list via `Packet::options`; the raw `options` field still exposes the untouched bytes. The magic cookie belongs to BOOTP's trailing `options` field, where RFC 2131 §3 puts it, so the DHCP layer starts at the first option and has `options` as its only field. Option 82 relay agent information (RFC 3046) is a nested option region of its own, walked by `bootp::RELAY_OPTIONS` and named (`agent_circuit_id`, `agent_remote_id`, `subscriber_id`, `link_selection`, `vendor_specific`, `relay_agent_flags`, `server_id_override`); the parsed sub-list encodes straight back. RFC 3396 concatenation joins a value split over repeated appearances of one code, joining the *octets* before anything decodes them, which is the only order that can rebuild a value whose halves do not each decode alone — half an address list, or half a nested region; Pad and End are left alone, which repeat by design. RFC 2131 §4.1 overload (option 52, now named) is honoured: `file` and then `sname` are walked as further option regions, in the order RFC 3396 §4 fixes | Remaining: joining means a message that split a value is rebuilt joined rather than split, so parse-then-rebuild is byte-exact only where the sender did not split — `wrpcap(rdpcap(f))` is unaffected either way, since it re-emits the buffer rather than a re-encoded option list; only the *first* option 52 selects the overload regions, so an option 52 inside `sname` or `file` is read as an ordinary option and never re-enters the walk, though its octets do join the outer one's under RFC 3396 and the value then reads as nonsense; the overload regions are read but never written, so `DHCP(options=...)` never overflows into `sname`/`file`; sub-option codes wiry does not name stay raw octets under their decimal label, as unnamed top-level options do | CLOSED |
| E8 | DNS record sections are parsed: `dns::parse_records` returns `qd`/`an`/`ns`/`ar` over the whole message, including name compression (RFC 1035 §4.1.4) with bounded pointer following, and decodes RDATA for A, NS, CNAME, SOA, PTR, MX, TXT, AAAA, SRV (RFC 2782), CAA (RFC 8659), OPT (RFC 6891) and the DNSSEC types DS, RRSIG, NSEC, NSEC3, NSEC3PARAM and DNSKEY (RFC 4034, RFC 5155), type bit maps included. An OPT pseudo-record also reports the fields RFC 6891 §6.1.3 puts in CLASS and TTL — UDP payload size, extended rcode, version and the DO bit — alongside its option list, each option named from the IANA EDNS0 registry. DNS over TCP works: `tcp.rs` dispatches port 53 and RFC 1035 §4.2.2's two-octet length prefix is a real `length` field that recomputes on write, with the twelve-octet header and the compression origin both shifted past it (see E1 framing). Names render in RFC 1035 §5.1 presentation form: a trailing root dot, and a dot or backslash inside a label escaped (RFC 4343 §2.1) | Remaining: the layer's payload still dissects as `Raw`, so bytes round-trip unchanged, and records are read but never written — there is no record encoder, which is also why a bare `DNS()` carries no question (E10). A TCP segment carrying more than one message dissects the first and leaves the rest in the payload; a write anywhere in such a packet therefore leaves the prefix alone rather than stretching it over the messages that follow, since a prefix already framing a shorter message describes bytes the layer does not own. `pkt[DNS].qd`/`an`/`ns`/`ar` are exposed from Python and listed by `fields()`, but they are parser-backed accessors (`proto::accessor_names`), not flat fields: they have no fixed offset or width and cannot be assigned. One message decodes at most 256 KB in total (`dns::MAX_DECODED_NAME_BYTES`) and returns what it read when that runs out, because a two-octet compression pointer yields up to 255 octets and a message claiming 65,535 records in every section otherwise amplified 2.75 MB of input into 568 MB of output. The budget charges every owned byte a record decodes to, not only names: a TXT character-string becomes an owned string, so RDATA of N zero octets yields N empty strings and uncharged that turned 17 MB of input into 656 MB; an NSEC type bit map turns 8,704 octets into 65,536 type numbers; an RRSIG signature, a DS digest and a DNSKEY public key are each bounded only by RDLENGTH. What the budget does *not* charge is the 112-octet `ResourceRecord` itself, so a section of minimal records — an empty name and no RDATA, eleven octets each — costs eleven input octets per record and about ten times that in memory. That factor is linear in the input, unlike the compression, TXT and bit-map cases the budget exists to break, and a walk cannot read more records than the input has room for, which `robustness.rs` asserts; charging the struct honestly would cap a message at ~2,300 records, below the ~5,900 a legitimate 64 KB stream message can hold, so the count is deliberately left bounded by the input length alone. No real message comes within a thousandth of the budget | PARTIAL |
| E9 | Source MAC defaults (`Ether.src`, `ARP.hwsrc`) stay zero at build time. `sendp` and `srp` fill an unset `Ether.src` from the outgoing interface at *send* time, on a copy | Scapy queries the live interface while building, which makes `bytes(Ether())` depend on the host. Keeping the fill in the send path is what leaves construction reproducible and `dev/build_matrix.py` at 38/38 without becoming environment-dependent. Remaining: `pcap::Device` carries no hardware address, so the address is read from `/sys/class/net/<if>/address` and is `None` on every other platform, which every caller treats as an ordinary outcome; `ARP.hwsrc` and `ARP.psrc` are not filled at all, so an ARP request built without them asks on behalf of 0.0.0.0. Byte output still differs from Scapy for these fields when built rather than sent | PARTIAL |
| E10 | Two more default-construction differences, both deliberate. A bare `DNS()` is the 12-byte header alone, where Scapy's ships a sample question record for `www.example.com`; writing a question needs the record encoder E8 still does not have, and inventing a hostname in a default is worse than an empty section. A bare `ICMP(type=13)` leaves the three timestamps zero, where Scapy fills them from the host clock, which is the E9 problem in another form: a default that changes between two runs of the same script | Every other layer is byte-identical to Scapy on default construction. `dev/api_audit.py` reports these two and ARP's interface MAC as the only remaining mismatches | OPEN |
| E11 | `flags` is a rich value, not a string. `pkt.flags` returns a `FlagValue` that compares equal to its integer and to its letter string, converts with `int()`/`str()`/`bool()`, hashes as its integer, exposes every bit as a boolean attribute where a concatenation of names is the AND of those bits (`.SA`), writes through to the packet when a bit is assigned, supports `&`, `|`, `^` and their in-place forms against an int, a string or another `FlagValue`, iterates its set names, and reprs as `<Flag 18 (SA)>`. Every `FieldKind::Flags` field has it, IPv4's and BOOTP's included. Names longer than a letter are joined with `+` (`MF+DF`), in the engine's renderer as well, so bulk columns and per-packet reads keep agreeing | Two bugs fell out of the work: an unassigned bit carries an empty name, which every string contains, so `BOOTP(flags="B")` used to set all sixteen; and TCP's control bits are nine wide, not eight, since NS (RFC 3540) takes the low bit of the reserved field. Bulk paths (`field_column`, `columns`) still return the plain string for a *flags* field, which costs one set lookup on the per-packet read path and no allocation; *option* fields now return the same parsed list from both. A name matching no flag raises rather than reading as zero, as scapy does, and matching is whole-token: substring matching meant that with names `a`, `ab` and `b` the wire value 2 read back as 7 | CLOSED |
| E12 | `Padding` is excluded from every enclosing length and checksum, and floats to the end during assembly: `IP()/Padding("abc")` has `len == 20` in a 23-byte frame, and `Raw/Padding/Raw/Padding` emits both `Raw` parts first. Dissection produces `Padding` too — IPv4, IPv6 and UDP declare the extent their length field claims, the walk stops there, and the trailer on a frame padded to Ethernet's 60-octet minimum becomes a `Padding` layer instead of transport data | Remaining: stacking `Padding` onto an already-dissected packet appends its bytes as payload rather than as a layer, because a materialised packet cannot be turned back into a field spec (same cause as the note in `__truediv__`). A capture clipped by the snaplen keeps the lengths the wire gave, since they describe bytes that were never captured; only the IPv4 header checksum, which covers present bytes, is still recomputed | PARTIAL |
| E13 | The conveniences scapy's suite leans on are implemented: `str` payloads (`Raw("abc")`, `pkt / "abc"`, `"abc" / pkt`, `add_payload`) encoded as latin-1, integer layer indexing (`pkt[0]`, `pkt[-1]`), `getlayer(IP, ttl=3)` with field filters and an occurrence count, the `pkt[IP::{"ttl": 3}]` slice form, `ls(pkt, verbose=True)`, iteration yielding one independent copy, and `copy()`. `wrpcap()` already accepted a mix of packet types | Address generators (`IP(dst=["a","b"])`, `IP(ttl=(5,10))`, `Net`) and hostname resolution in address fields are **out of scope and not planned**: a generator is a distinct feature that multiplies one declaration into many packets, and resolving a name at build time would put DNS in the build path. `rdpcap` and `PcapReader` now accept a binary stream as well as a path, which is what lets scapy's OSS-Fuzz regression inputs run against us; the stream is written to a temporary file first, because the reader indexes records by offset into one mapped buffer. gzip input is accepted too, by magic bytes rather than by file name, on the same path and for both formats; the trailing CRC is read past rather than enforced, so a capture cut off mid-transfer still yields the records that arrived, and a file name ending `.gz` compresses the output. Decompression is bounded, because a decompressor is a walk over an attacker-controlled length: output is written a chunk at a time rather than accumulated, the first chunk has to carry a pcap or pcapng magic, and the total is capped at `_MAX_GUNZIP` (4 GiB), so a 200 KB bomb that used to expand to nearly a gigabyte of resident memory is now refused at its first chunk. The remaining failures in `dev/scapy_suite.py` are the two `Net` generators and one test that asserts by patching `scapy.utils.warning`, which is a scapy internal we do not have | PARTIAL |

| E15 | `sniff` is keyword-only and takes `iface`, `count`, `store`, `prn`, `filter`, `lfilter`, `timeout`, `stop_filter`, `offline`, `quiet`, `promisc`, `snaplen`, plus the wiry extension `where=`. `count=0` is unbounded, `store=0` returns an empty `PacketList`, and `timeout` is scapy's wall-clock deadline for the whole call, not libpcap's read timeout. Filters AND together cheapest first: `filter=` BPF, then `where=`, then `lfilter=`. `AsyncSniffer` has `start`, `stop`, `join`, `.results` and `.running`, and `stop()` is honoured between packets on the offline driver too | Remaining, all deliberate: scapy is positional-tolerant where this is keyword-only; `session=`, `opened_socket=`, `started_callback=`, `L2socket=` and `monitor=` are not accepted and raise `TypeError` rather than being silently ignored; `offline=` takes a path or a `PacketList`, and a plain list of packets raises `NotImplementedError` naming `wrpcap` rather than growing a second state machine that never touches a capture buffer; `quiet=True` suppresses the printing of `prn`'s return value, which is the only output `sniff` produces here; `count` counts packets that survived every filter, as scapy's does; a `timeout` no `Duration` can hold (infinity, `1e300`) is no deadline at all, i.e. exactly `timeout=None`, where it used to panic the Rust side, and a negative one still expires at once; a BPF `filter=` needs the `live` feature even offline, because compiling one is libpcap's job, and without it raises `CaptureUnavailable` saying so. `AsyncSniffer` always installs a stop check on the offline driver, so that one takes the per-packet slow path even with no user callback. Live, `sniff(iface=...)` installs `filter=` on the handle so BPF runs in the kernel, releases the GIL across every read and polls `count`, `timeout` and the stop flag between reads rather than per matched packet; a callback-free live sniff runs the loop in 250 ms slices with the GIL released, reacquiring only to check for a signal so that an unbounded `sniff` still answers Ctrl-C. A live `AsyncSniffer` is a Rust thread owning the handle: `stop()` sets a flag the loop polls between reads, `join()` waits with the GIL released, and dropping one stops and joins it, with an `atexit` hook over a `WeakSet` of live sniffers as a second line. Those waits run in the same 250 ms slices the capture loop does, with a signal check between them, so Ctrl-C interrupts a shutdown as well as a capture; a `Drop` cannot raise, so an interrupt that lands during one is handed back to whatever runs next. A `prn` given to a live `AsyncSniffer` therefore runs on a non-Python thread and reacquires the GIL per packet, which is scapy's contract for async callbacks — and a `prn` calling `stop()` or `join()` on its own sniffer gets `RuntimeError: cannot join current thread`, which is what `threading.Thread.join()` says and what the offline driver in the same class already raised; the capture is still stopped, only the wait is refused. `start`, `stop` and `join` are serialised by a lock the sniffer holds only across the state change and never across a wait, so two threads cannot both start one sniffer, and one run is all a sniffer gets: starting a finished one raises rather than silently discarding its `.results` | PARTIAL |
| E16 | `conf` is a two-attribute stand-in for scapy's: `conf.iface`, resolved from libpcap on first read and settable, and `conf.verb`. `get_if_list`, `get_if_addr`, `get_working_if` and the wiry-only `interfaces()` are real where the `live` feature is on | Remaining: scapy's `conf` carries dozens of knobs (`conf.L3socket`, `conf.route`, `conf.checkIPaddr`, `conf.promisc`, …) and none of them exist. `conf.verb` is read by `send`, `sendp` and the `sr` family to decide whether to print a summary line, and by nothing else. `get_if_addr` returns the first IPv4 address or `0.0.0.0`, with no notion of scapy's routing table | OPEN |
| E17 | `send` and `sendp` take `x`, `inter`, `loop`, `count`, `verbose`, `return_packets` and `iface`. | E14 | Reply matching for `sr`/`sr1` (`answers.rs`) is a closed table: ICMP and ICMPv6 echo, an ICMPv4 error (types 3, 4, 5, 11, 12) quoting the datagram that provoked it, a swapped TCP or UDP address and port pair, that plus a DNS **response** (QR set) carrying the id a DNS **query** asked with, and an ARP reply for the address asked about. | E18 | Capture writing is streaming as well as bulk. `PcapWriter(filename, linktype=None, gz=False, endianness="", append=False, sync=False, nano=False, snaplen=65535, bufsz=4096)` takes a packet, a list, a `PacketList` or raw bytes per `write()` call, plus `flush()`, `close()` and the context-manager protocol; `PcapNgWriter` fixes the format, and `wrpcap()`/`wrpcapng()` are one-call wrappers over it that also take `append=True`. The format follows the file name (`.pcapng`/`.ntar`, `.gz`) unless `pcapng=`/`gz=` overrides it. The link type is settled from the first packet written and the header goes out then, so a writer opened before its packets exist still declares what it ends up holding; appending checks the existing file's format, link type, timestamp unit and byte order and refuses a mismatch rather than writing frames its header misdescribes (e2e4361 is the precedent), and for pcapng also checks that the file ends on a whole block — the trailing total length must locate a block header that agrees with it — because appending behind a half-written block buries both it and everything added after it. A refused append never writes: the existing bytes are untouched on every rejection path. Classic pcap gets no equivalent tail check, because its records carry no trailing length and nothing anchors the end of the file — finding a half-written final record means walking every record header from the front, which an append to a 368 MB capture should not have to pay — so appending behind a truncated pcap record still produces a tail no reader frames correctly. A compressed or file-object target is rewritten whole, through a temporary file and one `os.replace`, so a delivery that fails partway leaves the previous capture intact rather than truncated. `pkt.wirelen` carries the wire length through a round trip: the record index keeps `origlen` beside the captured length, so copying a snaplen-clipped capture writes the original wire length rather than collapsing it to the captured one, and a writer left open is closed by an `atexit` hook before finalisation, where `tempfile` and `gzip` can no longer be imported. `write(PacketList)` copies the whole capture inside Rust with the GIL released and mints no Python object — 791,615 packets, 368 MB, byte-identical, in 0.4 s — while `write(pkt)` crosses per packet, which is what a streaming writer is for. Both encode through the same `wiry-core` functions, and `tests/test_pcap_write.py` asserts the two produce the same file byte for byte | Remaining: `endianness=">"` raises `NotImplementedError`, since output is little-endian only; `bufsz` is accepted and ignored, the Rust sink doing its own buffering; a gzipped or file-object target is held in memory until `close()`, because the compressor is Python's, so a gzipped capture costs its uncompressed size in RAM and appending to one rewrites the whole file; a packet block written from a `PacketList` always names interface 0, so a pcapng whose interfaces declare different `if_tsresol` values is rewritten with the first one's unit for every record (the same single-flag limit the read side has, E5); `sync=True` flushes and `fsync`s once per `write()` call rather than once per packet; a timestamp that reaches the writer as `pkt.time` is a Python float, so at a present-day epoch it resolves to about 240 ns and `nano=True` cannot round-trip a nanosecond that the float never held — the file-to-file bulk path is exact, since it copies the stored integers without going through a float, and scapy avoids this by carrying `time` as a decimal; scapy's `RawPcapWriter`, `RawPcapNgWriter`, `.f` and `.fileno()` are not provided | PARTIAL |
