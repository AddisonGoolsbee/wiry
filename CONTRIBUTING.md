# Contributing to wiry

## Provenance (read before writing any protocol layer)

**wiry is a derivative work of Scapy, licensed GPL-2.0-only.** Reading Scapy and
copying from it is expected. GPL-2.0 permits that on three conditions, and a
patch that takes from Scapy must meet all three:

1. **The result stays GPL-2.0-only.** Not "or later": Scapy is version 2 only,
   and a derivative cannot widen the grant it inherited. Do not add a file under
   another licence, or a dependency whose licence is incompatible with GPL-2.0.
2. **Scapy's copyright notices are preserved**, in the file that carries the
   material.
3. **Modified files say they were modified, and when** (GPL-2.0 §2(a)).

### Recording what you took

Every file carrying Scapy-derived material opens with a provenance block. The
format, the ledger and the rules for when a block is required are in
[`NOTICE`](NOTICE); read that before your first such patch. In short:

```rust
// SPDX-License-Identifier: GPL-2.0-only
//
// Derived from scapy: scapy/layers/inet.py
//   scapy 2.7.0, upstream commit <sha>
//   Copyright (C) Philippe Biondi and the scapy contributors
//
// Changed by the wiry authors:
//   2026-09-18 — ported the TCP field table to the flat FieldDesc model
```

**Name the source exactly**: file path, version and commit. If a field table came
from `inet.py` and an enum from `dns.py`, name both. A file written from the RFC
alone gets no block, because the absence is itself a claim.

Add a row to the `NOTICE` ledger the first time a file gains derived material.
Each later change adds a dated line to that file's block. Never rewrite or delete
an existing line: the dates are the record §2(a) requires.

### Cite the RFC

Cite the RFC or IANA registry a layout follows, in the module's doc comment.
`dev/protogen/` refuses a spec without its `citation` key.

This is an accuracy control, not a licensing one. A specification is a better
source of truth than any implementation, Scapy included, and a field table that
disagrees with its cited RFC is a bug. Cite the spec, check the code against it,
and fix whichever is wrong in wiry.

### Off limits

- **A runtime dependency on Scapy.** GPL would allow it; the architecture does
  not. Importing Scapy for missing protocols puts one Python object per layer per
  packet back into the engine, which is what this project exists to remove.
  Unknown protocols dissect to `Raw` (`DEVIATIONS.md` S3).
- **Test vectors generated by running Scapy.** A suite whose expectations came
  from Scapy cannot detect that wiry and Scapy are both wrong, and code copied
  from Scapy makes that failure more likely. Build vectors from RFC examples,
  Wireshark/tshark output or public pcaps. `dev/parity_check.py` compares against
  Scapy as a development oracle; its output is never committed.
- **Code under a GPL-2.0-incompatible licence**, including Apache-2.0, and code
  whose provenance you cannot state.

If you are unsure whether a patch is derived, say so in the issue and record it as
derived. Over-attribution costs nothing; under-attribution is a licence
violation.

## Adding a protocol layer

A flat protocol is one TOML file in `dev/protogen/specs/`. The generator writes
the layer module, the `ProtoId`, the registration and the dispatch entry:

```sh
$EDITOR dev/protogen/specs/myproto.toml
python dev/protogen/protogen.py
```

It touches no shared file, so two people adding layers at once do not conflict.
Never edit generated output; edit the spec.

The generator does not read the RFC for you: the field table is written by hand,
offset by offset, against the specification you cite. Where the table also
derives from Scapy, the provenance block says so; the citation and the block are
separate records and both are required. `dev/protogen/README.md` has the spec
format, what the generator refuses to guess, and the hand-written region for what
the flat field model cannot express.

## Comments

Write as few as possible. A comment states what the code cannot: an invariant, a
bound and why it holds, the RFC section a layout follows, a portability trap, or
why a simpler-looking alternative is wrong. Do not narrate the next line, mark
sections, record history (the commit log does that) or hedge. Every `unsafe`
block in `wiry-pcap` carries a `// SAFETY:` comment naming the invariant it
relies on.
