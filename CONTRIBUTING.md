# Contributing to wiry

## Provenance policy (read this before writing any protocol layer)

**wiry is a derivative work of Scapy and is licensed GPL-2.0-only.** This is a
reversal: until the relicence commit, wiry was MIT and clean-room, and this file
told you never to open Scapy's sources. That rule is gone. Reading Scapy, and
copying from it, is now the plan.

What replaces it is not a weaker rule, just a different one. GPL-2.0 lets you
derive from Scapy on three conditions, and all three are on you when you send a
patch:

1. **The result stays GPL-2.0-only.** Not "or later" — Scapy is version-2-only,
   and a derivative cannot widen the grant it inherited. Every manifest says
   `GPL-2.0-only`; do not add a file under any other licence, and do not add a
   dependency whose licence is incompatible with GPL-2.0.
2. **Scapy's copyright notices are preserved.** They travel with the material
   into the file that carries it.
3. **Modified files say they were modified, and when** (GPL-2.0 §2(a)).

### Recording what you took

Every file carrying Scapy-derived material opens with a provenance block. The
format, the ledger and the rules about when the block is required are in
[`NOTICE`](NOTICE) — read that section before your first such patch. The short
version:

```rust
// SPDX-License-Identifier: GPL-2.0-only
//
// Derived from scapy: scapy/layers/inet.py
//   scapy 2.7.0, upstream commit <sha>
//   Copyright (C) Philippe Biondi and the scapy contributors
//
// Changed by the wiry authors:
//   2026-09-18 — ported the TCP field table to the flat FieldDesc model
```

**Be specific about the source.** "from scapy" is not a record; the file path,
the version and the commit are. If you took a field table from `inet.py` and an
enum from `dns.py`, name both. If you wrote a file from the RFC and took nothing,
it gets no block — the absence is itself a claim, so do not add one decoratively.

Add a row to the ledger in `NOTICE` the first time a file gains derived material.
A file changed again gains another dated line in its own block; never rewrite or
delete an existing line, because the dates are the record §2(a) asks for.

### The RFC citation is still required — for a different reason

Cite the RFC or IANA registry a layout comes from, in the module's doc comment,
exactly as before. `dev/protogen/`'s `citation` key is still a **required key**
and a spec without one still fails to generate.

**This is no longer a licensing control. Say so if someone asks.** It is an
accuracy control: a specification is a better source of truth than any
implementation, Scapy included, and a field table that disagrees with its cited
RFC is a bug worth catching before it ships. Citing the RFC and copying from
Scapy are not in tension — cite the spec, check the code against it, fix
whichever is wrong in wiry.

### What is still off limits

- **No runtime dependency on Scapy.** Unchanged, and no longer a licensing rule —
  GPL would permit it. It is an architecture decision: importing Scapy for
  unimplemented protocols puts one Python object per layer per packet back into
  the engine, which is the thing this project exists to remove. Unknown protocols
  dissect to `Raw`. See `DEVIATIONS.md` S3.
- **No golden test vectors generated by running Scapy.** Also not a licensing
  rule now. A suite whose expectations came out of Scapy cannot tell you that
  wiry and Scapy are both wrong, and now that wiry copies from Scapy that failure
  mode is more likely, not less. Build vectors from RFC examples,
  Wireshark/tshark output, or public pcaps. `dev/parity_check.py` compares
  against Scapy as a development oracle; it is not shipped and its output is
  never committed.
- **Code from anywhere that is not GPL-2.0-compatible.** Proprietary sources,
  Apache-2.0 code (incompatible with GPLv2 specifically), and anything whose
  provenance you cannot state.

If you are unsure whether a patch is a derivative or your own work, say so in the
issue and record it as derived. An over-attributed file costs nothing; an
under-attributed one is a licence violation.

## Adding a protocol layer

Do not hand-write the Rust. A flat protocol is one TOML file in
`dev/protogen/specs/`, and the generator writes the layer module, the `ProtoId`,
the registration and the dispatch:

```sh
$EDITOR dev/protogen/specs/myproto.toml
python dev/protogen/protogen.py
```

That is the whole workflow, and it touches **no shared file**, so two people
adding layers at the same time do not conflict.

It also makes the citation rule a build error rather than a review comment:
`citation` is a **required key**, and a spec without one does not generate. What
the generator does *not* do is read the RFC for you — the field table is still
written out by hand, one offset and width at a time, against the specification
you cite. Where the table is also derived from Scapy, the file's provenance block
says so; the citation and the block are separate records and both are required. `dev/protogen/README.md` has the spec format, the full list of things the
generator refuses to guess at, and the marked hand-written region that carries
the protocols the flat field model cannot express on its own.
